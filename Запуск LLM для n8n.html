Реально и комфортно: 7B модели (Qwen 2.5 7B, Llama 3.1 8B в q4/q5).

Можно попробовать: 14B в квантованном виде, но будет заметно медленнее.

Для генерации workflow обычно достаточно 7B: задача больше структурная, чем творческая.

Практический совет

Чтобы качество было заметно выше, дай модели 2–3 примера реальных workflow JSON из твоего n8n. LLM гораздо лучше копирует существующий паттерн, чем пытается угадать структуру с нуля. Это особенно помогает с версиями узлов и параметрами.

Можно пойти ещё дальше: сделать в n8n отдельный workflow-генератор. Пользователь пишет задачу → AI Agent → Structured Output → сохраняет JSON → сразу импортирует/создаёт черновик workflow. n8n как раз активно развивает AI Agent и шаблоны workflows.

Скептический момент: генерация workflow не всегда даёт рабочий результат с первого раза. Версии узлов, креденшелы и мелкие поля часто требуют ручной правки. Поэтому лучший режим — AI как черновик + ручная проверка, а не полностью автономная генерация. Даже сами n8n и сообщество больше продвигают шаблоны и AI-ассистированную сборку, чем «идеальный one-shot генератор».

Ответ 2

Да — это вполне реально и, на мой взгляд, это один из самых полезных способов «пощупать» n8n с локальной LLM. Схема обычно такая:

Архитектура

Промпт → локальная LLM (через Ollama) → JSON workflow → n8n Import

Идея: модель генерирует JSON в формате n8n, который потом импортируется в редактор.

Самый практичный стек

Ollama

Запускает локальные модели. У тебя уже есть опыт с ним — это удобно.

Для генерации workflow хорошо подходят модели с сильными инструкциями:

  1. Qwen3 14B / 32B (если есть возможность)

    Сильны в структурированном JSON.

  2. DeepSeek-R1 / DeepSeek-V3

    Хорошо рассуждают, но могут быть многословны — проси выводить только JSON.

  3. Llama 3.1 8B/70B

    Работает, но иногда требует более жёсткого промпта.

Важно

Лучше давать модели шаблон рабочего workflow.

Попроси n8n экспортировать простой workflow (например, Webhook → Set → Respond). Это даст модели правильную структуру: nodes, connections, position, typeVersion. Без примера модели часто ошибаются в схеме.

Что реально хорошо автоматизируется LLM

  1. Создание каркаса workflow.

  2. Генерация выражений n8n ({{$json.field}}).

  3. Построение ветвлений (IF/Switch).

  4. Генерация HTTP-запросов к API.

  5. Создание AI-агентов и RAG-пайплайнов.

Скептически

Сложные production-workflow лучше проверять вручную.

Особенно credentials, retries, error handling и idempotency. LLM часто делает логически правдоподобный, но не полностью корректный JSON.

Хочешь максимально удобно?

Сделай себе «генератор workflow» в самом n8n:

  1. Webhook (принимает описание задачи).

  2. HTTP Request → Ollama.

  3. Code node — валидирует JSON.

  4. Write Binary File — сохраняет .json.

  5. Telegram/Email — отправляет файл.

Тогда ты сможешь писать: «сделай workflow для парсинга RSS и публикации в Telegram», а n8n сам будет генерировать импортируемый JSON.

Для старта я бы сделал минимальный цикл

  1. Установить Ollama.

  2. Запустить n8n.

  3. Экспортировать один простой workflow из n8n.

  4. Скормить его модели как пример.

  5. Попросить сгенерировать похожий workflow.

  6. Импортировать и протестировать.
